## 目的
`commit-task.sh` は verify を実行しないため `.agent-runs/<TASK>/verify.log` が作られず、
orchestrate スキルの「verify FAIL ならログ末尾を添えてワーカーに差し戻す」手順と噛み合っていない。
また、呼び出し側がメッセージに `T-xxx:` を付けると `T-002: T-002: ...` と二重になる。

## 仕様
`scripts/commit-task.sh <TASK> "<メッセージ>"` の振る舞いを次のように変える。

1. メッセージ先頭が `<TASK>:`（コロン後の空白は任意）なら取り除いてからコミットする
   - 例：`commit-task.sh T-002 "T-002: foo"` → コミットメッセージ `T-002: foo`
   - 取り除いた結果が空なら `die`（終了コード 1）
2. コミット成功後、`"$ROOT/scripts/verify.sh" "$WT"` を実行し、出力を `"$(run_dir "$TASK")/verify.log"` に保存する
   - `codex-fix.sh` の 43〜47 行目と同じ書き方に揃える（PASS は `log`、FAIL は `warn` で最終行を表示）
3. 終了コード
   - 0：コミット成功かつ verify PASS
   - 1：引数エラーなど（既存どおり）
   - 3：files_allowed 外の変更（既存どおり。verify は実行しない）
   - 4：コミットは成功したが verify FAIL（新規）
4. 変更がない場合（既存の「コミットをスキップ」）も verify は実行し、結果に応じて 0 / 4 を返す
   （opencode-worker.sh の後に呼ばれたとき、ログを最新にするため）

`.claude/skills/orchestrate/SKILL.md` の「2. 完了処理」を上記に合わせて更新する：
- commit-task.sh が verify まで行い、`verify.log` を書くこと
- 終了コード 4 のときにワーカーへ1回差し戻すこと
- メッセージに `T-xxx:` を付けなくてよい（付けても重複しない）こと

## 受け入れ条件
オーケストレーターが worktree 上で次を確認する（bash スクリプトのため vitest の対象外）。
- [ ] `bash -n scripts/commit-task.sh` が通る
- [ ] 変更なしの worktree で実行すると verify が走り、`.agent-runs/<TASK>/verify.log` が作られ、終了コード 0
- [ ] `"<TASK>: msg"` を渡しても接頭辞が二重にならない（ロジックを読んで確認できる程度に単純な実装にする）
- [ ] bash 3.2（macOS 標準）で動く書き方にする。全角文字の直後に `$VAR` を置かず `${VAR}` を使う（b2fdb49 と同じ問題を避ける）
- [ ] `npm run verify` が通る
