## 目的
`npm run verify` は src/ の TypeScript しか見ておらず、`scripts/*.sh` の変更を検証できない。
設定ファイル（package.json / tsconfig / eslint / vitest）を変えずに、vitest の既定の探索範囲（`**/*.test.ts`）に
テストを置いて、verify で運用スクリプトも検証されるようにする。

## 仕様
`scripts/scripts.test.ts` を新規作成する（vitest、Node 標準ライブラリのみ。`node:child_process` / `node:fs` / `node:os` / `node:path`）。

### 1. 構文チェック
- `scripts/` 直下の `*.sh` をすべて列挙し、1ファイルずつ `bash -n <file>` が終了コード 0 になることを確認する（`it.each` などでファイルごとに1テスト）
- 同じく1ファイルずつ `shellcheck -S warning <file>` が終了コード 0 になることを確認する（info 以下の指摘は対象外）
  - `shellcheck` が見つからない場合はテストを **失敗** させ、メッセージに「shellcheck をインストールしてください（brew install shellcheck）」と出す（skip にしない）
- ファイル一覧はテスト実行時に `readdirSync` で取る（ハードコードしない）

### 2. AGENTS.md
「技術スタック」に1行追加する：`- 運用スクリプトの検査に shellcheck を使う（npm run verify の前提。brew install shellcheck）`

### 3. commit-task.sh のスモークテスト
テストごとに `mkdtemp` で一時ディレクトリを作り、その中に最小の git リポジトリを用意する：
- `git init`、初期コミットを1つ作る
- このテストファイルと同じ worktree の `scripts/lib.sh`、`scripts/commit-task.sh` をコピーする
- `team.config.sh`（リポジトリ直下のものをコピー）
- `tasks/T-999.md`：front matter に `files_allowed: [src/a.ts]`
- `scripts/verify.sh`：スタブ。環境変数 `STUB_VERIFY` が `fail` なら `echo "VERIFY: FAIL (test)"; exit 1`、それ以外は `echo "VERIFY: PASS"`
- `.worktrees/T-999` として `git worktree add` で worktree を作る（`commit-task.sh` は `wt_path` = `<ROOT>/.worktrees/<TASK>` を見るため）
- git の author / committer は環境変数（`GIT_AUTHOR_NAME` など）で与え、利用者のグローバル設定に依存しない
- `afterEach` で一時ディレクトリを削除する

確認するケース：
| ケース | 期待 |
| --- | --- |
| `src/a.ts` を追加し `commit-task.sh T-999 "foo"` | 終了コード 0、最新コミットのメッセージが `T-999: foo`、`.agent-runs/T-999/verify.log` の最終行が `VERIFY: PASS` |
| メッセージ `"T-999: foo"` | コミットメッセージが `T-999: foo`（接頭辞が二重にならない） |
| メッセージ `"T-999:"` | 終了コード 1、コミットが増えない |
| `src/b.ts`（files_allowed 外）を追加 | 終了コード 3、コミットが増えない、verify.log が作られない |
| `STUB_VERIFY=fail` で `src/a.ts` を追加 | 終了コード 4、コミットは作られている |
| 変更なしで実行 | 終了コード 0、verify.log が作られる |

## 入力と不正入力
- メッセージが接頭辞のみ（`T-999:`）→ commit-task.sh は終了コード 1（上表で確認）
- `bash` が PATH にない環境は想定しない（macOS / Linux の開発機のみ）

## レビュー観点チェックリスト
- 境界値：変更なし・接頭辞のみのメッセージを含める（上表）
- 日付：該当なし
- 引数：接頭辞の有無・空白の有無
- 取り違え：「コミットが増えない」は実行前後の `git rev-list --count HEAD` を比べて確認する
- 並行実行：テストごとに別の一時ディレクトリを使い、テスト同士がリポジトリやファイルを共有しない。実在のリポジトリ（このプロジェクト自身）の git 状態・`.agent-runs/` を一切変更しない
- タイムアウト：各テストは数秒以内。必要なら `it` の timeout を 20 秒程度に設定する
