## 目的
T-004 のレビューが3往復かかったのは、余分な引数や存在しない日付など、指示書に書かれていない入力の扱いが1件ずつ指摘されたため。
ほかのタスクでも、並行実行や境界の日付（T-002、T-003）が初回レビューで major になった。
指示書の段階で入力仕様とレビュー観点を明示し、往復を減らす。

## 仕様
### templates/task.md
「## 仕様」と「## 受け入れ条件」の間に、次の2節を追加する（見出し名はこのとおり）。

```
## 入力と不正入力
<!-- 受け入れる入力の範囲と、不正入力のときの振る舞い（例外の型／終了コード／出力先とメッセージ）を列挙する。
     例：余分な位置引数、存在しないID、形式は正しいが実在しない日付（2026-02-30）、空文字、空配列 -->

## レビュー観点チェックリスト
<!-- 該当しないものは「該当なし」と書く。ワーカーはこれをテストで押さえる -->
- [ ] 境界値：空・0件・存在しないID・最大/最小
- [ ] 日付：実在しない日付、月末・年末・うるう年、西暦0〜99年
- [ ] 引数：余分な引数・重複指定・未知のオプション
- [ ] 取り違え：ID と件数・インデックスの混同
- [ ] 並行実行：同時呼び出しで一時ファイル名などが衝突しないか
```

### templates/worker-prompt.md
「# 進め方」の手順 2 の前に1項目追加する：
「指示書の『入力と不正入力』『レビュー観点チェックリスト』の各項目に対応するテストを書く。該当なしの項目は報告の懸念欄に書かなくてよい」
（番号は振り直す。`{{...}}` プレースホルダーは変えない）

### .claude/skills/plan-tasks/SKILL.md
手順 2 の分解の基準に1行追加する：
「『入力と不正入力』『レビュー観点チェックリスト』を必ず埋める（該当なしも明記）」

## 入力と不正入力
該当なし（ドキュメントのみの変更）

## レビュー観点チェックリスト
該当なし（ドキュメントのみの変更）

- [ ] `npm run verify` が通る
