## 目的
T-005 以降、`commit-task.sh` がコミット後に verify を実行して `verify.log` を書く。
`codex-fix.sh` はその後に自分でも verify を実行しているため、同じ verify が2回走る。
また `set -e` の下で `commit-task.sh` の終了コード 4（verify FAIL）がそのまま伝わり、
ヘッダに書かれた「1=失敗」と食い違っている。

## 仕様
`scripts/codex-fix.sh` の末尾（`commit-task.sh` 呼び出し以降）を次のように変える。

1. `codex-fix.sh` 自身の verify 実行（`verify.sh` を呼ぶ if ブロック）を削除する。verify は `commit-task.sh` に任せる
2. `commit-task.sh` の終了コードを次のように変換して終了する
   - 0 → 0（verify PASS。ログ出力は commit-task.sh が行うので追加しない）
   - 4（verify FAIL）→ 1
   - 3（files_allowed 外の変更）→ 3
   - それ以外 → 1
   - `set -e` で即終了しないよう `|| rc=$?` の形で受ける
3. 同ファイル内の shellcheck 警告 SC2155（`export X="$(...)"`、17・26・27 行目付近）を、宣言と代入を分ける形に直す
   （`X="$(...)"` の後に `export X`）。`shellcheck -S warning scripts/codex-fix.sh` が警告なしになること
4. ヘッダコメントの終了コードを `0=修正後 verify PASS / 1=失敗（verify FAIL を含む） / 3=files_allowed 外の変更` に更新する

`.claude/skills/orchestrate/SKILL.md` の「3. レビューループ」に1行追加する：
「`codex-fix.sh` が終了コード 3（files_allowed 外の変更）で止まったら、内容を確認して人間に判断を仰ぐ」

## 入力と不正入力
- 引数・既存のエラー処理（タスクIDなし、レビュー結果なし、Codex 失敗）は変更しない
- `commit-task.sh` の想定外の終了コード（1, 2, 5 など）は 1 に丸める

## レビュー観点チェックリスト
- 境界値：commit-task.sh の終了コード 0 / 3 / 4 / その他 の4通りを網羅しているか
- 日付：該当なし
- 引数：該当なし（引数仕様は変えない）
- 取り違え：`$?` を別コマンドの後に読んでいないか（`|| rc=$?` の直後に読む）
- 並行実行：該当なし
- bash 3.2（macOS 標準）で動くこと。全角文字の直後に `$VAR` を置かず `${VAR}` を使う

## 受け入れ条件
- [ ] `bash -n scripts/codex-fix.sh` が通る
- [ ] `shellcheck -S warning scripts/codex-fix.sh` が終了コード 0
- [ ] `codex-fix.sh` 内に `verify.sh` の呼び出しが残っていない
- [ ] `npm run verify` が通る
