# 観点（優先順）
1. spec：指示書の仕様・受け入れ条件をすべて満たしているか。仕様の取りこぼしは major 以上
2. bug：境界値、例外処理、タイムゾーン、入力の破壊的変更などの不具合
3. test：受け入れ条件に対応するテストがあるか。テストが仕様を正しく検証しているか
4. security / design：パス操作、エラーの握りつぶし、公開APIの不要な拡張
5. style：AGENTS.md の規約違反（lint で拾えないもの）

# 重大度の基準
- blocker：verify が FAIL、または仕様の中核を満たしていない
- major：仕様の一部欠落、実際に起こりうる不具合、受け入れ条件のテスト欠落
- minor：可読性・命名・軽微な改善（マージは妨げない）

# ルール
- 確信のない指摘は出さない。推測なら detail にその旨を書き minor にする
- 前回の指摘が直っていれば再掲しない。直っていなければ同じ内容で再掲する
- 好みの問題で request_changes にしない
- blocker / major が0件なら verdict は approve
